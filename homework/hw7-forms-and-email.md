## Часть 1: Форма — `components/feedback/FeedbackForm.tsx`

Форма содержит три поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | text input | Имя пользователя |
| `temperature` | number input | Фактическая температура |
| `weather` | select | Тип погоды |

Варианты для select: `sunny` / `cloudy` / `rainy` — отображай по-русски, значения можешь хранить на английском.

**Состояния которые нужны:**

```ts
const [name, setName] = useState('')
const [temperature, setTemperature] = useState('')
const [weather, setWeather] = useState('sunny')
const [clientError, setClientError] = useState<string | null>(null)
const [serverError, setServerError] = useState<string | null>(null)
const [success, setSuccess] = useState(false)
const [isLoading, setIsLoading] = useState(false)
```

**Клиентская валидация — выполняется до отправки на сервер:**

- Имя не может быть пустым
- Имя не может быть короче 2 символов

Проверяй при сабмите, до вызова server action. Если не прошло — выставляй `clientError` и не отправляй.

**Сабмит:**

```tsx
async function handleSubmit(e: React.FormEvent) {
    e.preventDefault()
    setClientError(null)
    setServerError(null)

    // 1. клиентская валидация
    // 2. setIsLoading(true)
    // 3. вызов server action
    // 4. обработка результата
    // 5. setIsLoading(false)
}
```

Server action возвращает результат — либо успех, либо ошибку с текстом. Реши сам какую структуру вернуть.

**После успешной отправки** — показывай сообщение "Спасибо! Мы получили твой отзыв." вместо формы.

**Пока загружается** — кнопка должна быть задизейблена и менять текст на "Отправляем...".

## Часть 2: Server Action — `app/actions/feedback.ts`

```ts
"use server"
```

Принимает данные формы. Валидирует на сервере. Вызывает функцию из `lib/email.ts`. Возвращает результат.

**Серверная валидация:**

- Температура должна быть числом
- Температура от -50 до +50

Почему валидируем на сервере если уже проверяли на клиенте? Потому что клиентский код можно обойти. Server action — это публичный endpoint, он может быть вызван напрямую без браузера.

**Структура ответа** — подумай сама, но вот одна из возможных:

```ts
type ActionResult =
    | { success: true }
    | { success: false; error: string }
```

**Почему здесь не бросаем, а возвращаем ошибку:**

На прошлом уроке мы бросали исключения из server action — и это правильно для навигационных ошибок ("город не найден" → `notFound()`). Но форма — другой сценарий.

Когда пользователь ввёл температуру +200 — это не технический сбой, это **ожидаемый исход**. Форма должна остаться на экране, показать сообщение об ошибке и дать исправить. Если бросить исключение — Next.js покажет экран ошибки и форма исчезнет.

Правило: бросай исключение когда продолжать работу невозможно. Возвращай ошибку в значении когда это ожидаемый исход который UI должен обработать.

```
Исключение → ошибка приложения, нужен error boundary
Возвращаемая ошибка → ожидаемый исход, UI решает что показать
```

Не бросай исключение из server action наружу — поймай его внутри и верни `{ success: false, error: "..." }`. Это другой "философский" подход к обработке ошибок, который лучше подходит для форм и API.

## Часть 3: Отправка письма — `lib/email.ts`

Используем [Resend](https://resend.com) — бесплатный сервис для отправки email, без SMTP и сложной настройки.

**Установка:**
```bash
npm install resend
```

**Регистрация:** зайди на resend.com, создай аккаунт, получи API ключ в разделе API Keys.

**Функция отправки:**

```ts
import { Resend } from 'resend'

const resend = new Resend(process.env.RESEND_API_KEY)

type FeedbackData = {
    name: string
    temperature: number
    weather: string
}

export async function sendFeedbackEmail(data: FeedbackData): Promise<void> {
    const { error } = await resend.emails.send({
        from: 'onboarding@resend.dev',     // на бесплатном тарифе только этот адрес
        to: process.env.FEEDBACK_EMAIL!,    // твоя почта куда придёт письмо
        subject: `Отзыв о погоде от ${data.name}`,
        text: `
Имя: ${data.name}
Фактическая температура: ${data.temperature}°C
Погода: ${data.weather}
        `.trim()
    })

    if (error) {
        throw new Error(`Не удалось отправить письмо: ${error.message}`)
    }
}
```

Эта функция только отправляет письмо. Никакой валидации, никакого знания о форме — это задача server action.

> Обрати внимание: `from: 'onboarding@resend.dev'` — это специальный адрес для тестирования на бесплатном тарифе Resend. Письма будут приходить только на почту которую ты указала при регистрации. Для продакшна нужно подтвердить свой домен.

## Часть 4: Секреты — переменные окружения

Никогда не храни API ключи в коде. Для этого есть `.env.local`.

**Создай файл `.env.local` в корне проекта:**

```
RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
FEEDBACK_EMAIL=твоя@почта.com
```

**Проверь `.gitignore`** — `.env.local` должен быть там. Если нет — добавь. Иначе ключ уйдёт в репозиторий.

**Как использовать в коде:**

```ts
process.env.RESEND_API_KEY   // только на сервере
```

Переменные без префикса `NEXT_PUBLIC_` доступны только на сервере — это правильно. Ключ не должен попасть в браузер.

**Проверь что всё настроено:**
```ts
if (!process.env.RESEND_API_KEY) {
    throw new Error('RESEND_API_KEY не настроен')
}
```

Можно добавить такую проверку в начало `lib/email.ts` — упадёт с понятной ошибкой при запуске, а не при первой отправке.

## Часть 5: Встраиваем на страницу города

`FeedbackForm` живёт прямо на странице города — `app/city/[cityID]/page.tsx`. Никакой отдельной страницы не нужно. Добавь компонент под карточкой погоды с заголовком "Данные неточные? Сообщи нам".

Серверный компонент рендерит клиентский — это нормально и правильно.

## Что должно получиться

1. Пользователь открывает страницу города, видит форму под прогнозом
2. Вводит имя меньше 2 символов — сразу видит ошибку, форма не отправляется
3. Вводит температуру +200 — server action отвечает ошибкой, форма показывает её
4. Вводит всё корректно — письмо приходит на почту, форма показывает "Спасибо!"
5. Пока идёт отправка — кнопка задизейблена
