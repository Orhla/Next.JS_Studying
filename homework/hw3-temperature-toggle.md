# Домашнее задание 3: Свитчер единиц температуры

## Цель

Добавить кнопку, которая переключает температуру между °C и °F.
Будем делать в три шага — сначала маленький и локальный, потом поднимем стейт выше, потом столкнёмся с ограничениями пропсов.

---

## Часть 1: Кнопка внутри одного компонента

**Файл:** `components/weather/WeekForecast/AverageTemperature.tsx`

Сейчас компонент просто показывает среднюю температуру в Цельсиях.  
Твоя задача — добавить кнопку `°C / °F` прямо внутри него.

### Новые концепты
**`useState`** — хук, который даёт компоненту "память". Позволяет хранить значение между рендерами и обновлять его.

```tsx
const [unit, setUnit] = useState<"C" | "F">("C")
```

- `unit` — текущее значение
- `setUnit` — функция сеттер, которая меняет значение и перерисовывает компонент
- `"C"` в конце — начальное значение

**`onClick`** — пропс кнопки, принимает функцию. Эта функция вызывается при клике.

```tsx
<button onClick={() => setUnit(unit === "C" ? "F" : "C")}>
  °C / °F
</button>
```

### Формула перевода

```
F = C * 9/5 + 32
```

### Что должно получиться

- Компонент показывает среднюю температуру
- Рядом кнопка `°C / °F`
- При клике температура пересчитывается и единица меняется

## Часть 2: Поднятие стейта

Кнопка в `AverageTemperature` работает, но температура на карточках дней (`DayCard`) по-прежнему всегда в Цельсиях. Нужно, чтобы они тоже реагировали на переключение.

### Проблема

Стейт `unit` сейчас живёт внутри `AverageTemperature`. Компонент `DayCard` ничего о нём не знает — они "не связаны".

### Решение: поднять стейт к общему родителю

`WeekForecast` — это родитель и `AverageTemperature`, и `DayCard`. Если перенести `useState` туда, можно передать `unit` в оба компонента через пропсы.

Это называется **lifting state up** (поднятие стейта).

### Шаги

**1. Переименуй `WeekForecast.tsx`**

Компонент теперь будет делать больше, чем просто показывать прогноз — он управляет состоянием. Хорошее название: `WeatherDashboard`. Переименуй файл и компонент.

**2. Перенеси `useState` в `WeatherDashboard`**

**3. Добавь в `AverageTemperature` проп `onToggle`**

Кнопка **остаётся** в `AverageTemperature`, но теперь она не управляет своим стейтом — она вызывает функцию, которую ей передал родитель.

Это новый концепт: **функция как проп**. Дочерний компонент говорит родителю "кнопку нажали", а родитель решает что с этим делать.

```tsx
type Props = {
    avgTemp: number
    unit: "C" | "F"
    onToggle: () => void
}
```

Кнопка внутри `AverageTemperature`:
```tsx
<button onClick={onToggle}>°C / °F</button>
```

**4. Добавь кнопку в `WeatherDashboard`**

Кнопка переключения есть и здесь — она вызывает `setUnit` напрямую.

**5. Передай нужные пропсы вниз**

- В `AverageTemperature` — `unit` и `onToggle` (передай туда `() => setUnit(unit === "C" ? "F" : "C")`)
- В `DayCard` → `TempRange` — только `unit`, кнопки там нет

### Что должно получиться

- Кнопка `°C / °F` есть и в `WeatherDashboard`, и в `AverageTemperature`
- Обе кнопки работают и переключают температуру везде — потому что обе меняют один и тот же стейт в `WeatherDashboard`

## Часть 3: Переключатель на странице детального дня

Открой страницу `/day/[дата]` — там тоже показывается температура, но переключателя нет.

### Вопрос

Можно ли передать `unit` из `WeatherDashboard` на эту страницу через пропсы?

**Нет.** Это разные страницы — разные маршруты Next.js. Между ними нет общего дерева компонентов, поэтому пропс передать некуда. Стейт из одной страницы не "доживает" до другой.

### Решение для этого задания

Добавь **свой независимый** `useState` на странице деталей.

**Файлы для изменений:**
- `components/weather/DayDetail/DayDetail.tsx` — сюда добавь `useState` и кнопку
- `components/weather/DayDetail/WeatherStats/MaxTempItem.tsx` и `MinTempItem.tsx` — добавь проп `unit` и пересчитывай температуру

### Что должно получиться

- На странице детального дня своя кнопка `°C / °F`
- При переключении меняются min и max температура

### Что заметить

Если на главной странице переключить в °F, а потом перейти на детальную — там будет °C. Каждая страница "не знает" о состоянии другой.

Именно для решения этой проблемы существует **React Context** (или локал стораж) — но это уже следующая тема.
