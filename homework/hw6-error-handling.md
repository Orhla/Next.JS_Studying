## Часть 2: Поиск города — геокодинг с полной обработкой ошибок

Мы перерабатываем компонент `CityCelector`. Раньше он брал города из константы. Теперь при вводе 3-4 букв мы будем запрашивать данные у сервера,
сервер отвечает нам списком городов, мы показываем их пользователям, а он выбирает. Т.е. то, что пользовател ввел в строку поиска -   
надо отправить на сервер и посмоотреть какие города подходят. Например "Берли" — может быть "Берлин" из германии, "Берли" - город в Англии, "Берли" - деревня в России.
И пользователь выбирает нужный ему город. И после этого мы сохраняем этот именно город в кукис и теперь показываем именно этот город. Приложение становится не по 3м 
городам, а по всему миру.

### API

open-meteo предоставляет бесплатный геокодинг без ключа:

```
https://geocoding-api.open-meteo.com/v1/search?name=<CITY-QUERY>&count=5&language=ru&format=json
```

Открой эту ссылку в браузере. Посмотри на структуру ответа — результаты лежат в поле `results`. Если ничего не найдено — поля `results` в ответе нет вообще.

Мы должны обрабатывать ошибки многоуровнево. Например, если пропал интернет — `fetch` бросит исключение. Если сервер ответил 500 — `fetch` не бросит
исключение, но `response.ok` будет `false`. Если сервер вернул не JSON — `response.json()` бросит исключение. И так далее.

### Концепт: многоуровневая обработка ошибок

Один `fetch` может упасть на нескольких уровнях — и каждый нужно обработать отдельно:

```
1. Сеть        — fetch() бросает исключение (нет интернета, DNS не резолвится)
2. HTTP        — response.ok === false (сервер ответил 4xx или 5xx)
3. Данные      — response.json() бросает исключение (ответ не JSON)
4. Структура   — данные пришли, но поля не те что ожидали
5. Бизнес-логика — данные валидны, но результатов нет
```

Мы по прежнему хотим правильные слои:
- компонент - работает с состоянием и UI
- библиотека - работает с сетью, данными и ошибками
